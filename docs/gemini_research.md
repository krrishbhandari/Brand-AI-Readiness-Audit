A. Strong AI Visibility vs. Weak AI Visibility
Technical Accessibility: Sites with strong visibility rely on Server-Side Rendering (SSR) or static HTML generation. Headless LLM crawlers (e.g., GPTBot, PerplexityBot) receive full plain-text responses on initial HTTP GET requests. Weak visibility sites heavily use Client-Side Rendering (CSR) or single-page applications (SPAs), serving empty <div id="root"> shells that require expensive JS execution.  
PDF
+ 2

Content Extraction Efficiency: Strong sites adopt a "Fact-First" structure. The first paragraph under an H2 contains a direct, unambiguous answer, followed by structured tables or bullet points. Weak sites bury answers under multi-paragraph fluff, intro narrative, or marketing jargon.  
PDF
+ 2

Semantic Tagging: Strong sites utilize rich JSON-LD Schema (Product, SoftwareApplication, DefinedTerm, MedicalCondition), allowing RAG extractors to parse key entities without statistical guessing. Weak sites have missing or malformed schema, forcing LLMs to rely entirely on unstructured heuristics.  
PDF
+ 1

B. Weak AI Visibility vs. Misrepresented by AI
Invisibility vs. Hallucination: A site with weak visibility is simply omitted from answers (e.g., an LLM recommends 3 competitor products and ignores the unindexed brand). A site that is misrepresented active damages the brand because the AI serves incorrect prices, discontinued features, or false safety warnings.

+ 1

Crawler Blockade: The brand blocks GPTBot or ClaudeBot in robots.txt or edge CDN firewalls. The LLM cannot fetch the owned site and relies on unverified, outdated 3rd-party forum posts or scrapers.

+ 1

Entity Ambiguity (Mistaken Identity): The brand shares a name with another entity (e.g., Fintech Startup X vs. Crypto Token X) and lacks sameAs schema linking to authoritative databases (Wikidata, Crunchbase).  
PDF

Fact Uncorroborated & Stale: The brand claims a specification on its homepage, but every external news outlet or review site cites a different, older specification. RAG engines prioritize third-party multi-source consensus over single-source owned claims.

def clean_text(html_content):
    """Strips scripts, styles, and extracts visible clean text."""
    if not html_content:
        return ""
    soup = BeautifulSoup(html_content, "html.parser")
    for element in soup(
        ["script", "style", "nav", "footer", "noscript", "header"]
    ):
        element.decompose()
    text = soup.get_text(separator=" ")
    return " ".join(text.split())


def count_json_ld(html_content):
    """Counts <script type="application/ld+json"> blocks."""
    if not html_content:
        return 0
    soup = BeautifulSoup(html_content, "html.parser")
    return len(
        soup.find_all("script", attrs={"type": "application/ld+json"})
    )


def check_robots_txt(domain):
    """Checks robots.txt existence and AI bot Disallow directives."""
    robots_url = f"https://{domain}/robots.txt"
    try:
        resp = requests.get(robots_url, headers=HEADERS, timeout=8)
        if resp.status_code != 200:
            return f"HTTP {resp.status_code}", "no", ""

        lines = resp.text.splitlines()
        current_agent = "*"
        blocked_bots = set()

        for line in lines:
            line = line.strip().lower()
            if line.startswith("user-agent:"):
                current_agent = line.split(":", 1)[1].strip()
            elif line.startswith("disallow:") and len(line.split(":", 1)[1].strip()) > 1:
                if current_agent in AI_BOTS:
                    blocked_bots.add(current_agent)
                elif current_agent == "*":
                    blocked_bots.add("all_wildcard")

        if blocked_bots:
            return "200 OK", "yes", ", ".join(blocked_bots)
        return "200 OK", "no", "none"
    except Exception as e:
        return "error", "unknown", str(e)[:30]


def check_sitemap(domain):
    """Checks sitemap.xml existence and estimates URL count."""
    sitemap_url = f"https://{domain}/sitemap.xml"
    try:
        resp = requests.get(sitemap_url, headers=HEADERS, timeout=8)
        if resp.status_code != 200:
            return "no", 0

        # Quick count of <loc> tags in sitemap XML
        loc_count = len(re.findall(r"<loc>", resp.text, re.IGNORECASE))
        return "yes", loc_count
    except Exception:
        return "no", 0


def fetch_raw_html(url):
    """Fetches static raw HTML without executing JavaScript."""
    try:
        resp = requests.get(url, headers=HEADERS, timeout=12)
        return resp.status_code, resp.text
    except Exception as e:
        return 0, ""


def fetch_rendered_html(url, page):
    """Fetches rendered DOM after JavaScript execution via Playwright."""
    try:
        page.goto(
            url, wait_until="networkidle", timeout=20000
        )  # 20 second timeout
        content = page.content()
        return content
    except Exception:
        try:
            # Fallback to domcontentloaded if networkidle times out
            content = page.content()
            return content
        except Exception:
            return ""


def find_missing_snippet(raw_text, rendered_text):
    """Extracts a short snippet of text present in rendered HTML but absent in raw HTML."""
    if len(rendered_text) <= len(raw_text):
        return "None"

    raw_words = set(raw_text.split())
    rendered_words = rendered_text.split()

    missing_chunks = []
    current_chunk = []

    for word in rendered_words:
        if word not in raw_words:
            current_chunk.append(word)
        else:
            if len(current_chunk) >= 5:  # meaningful sequence
                missing_chunks.append(" ".join(current_chunk))
            current_chunk = []

    if missing_chunks:
        snippet = missing_chunks[0][:80]
        return f'"{snippet}..."'
    return "Minor DOM reordering/hydration"


def audit_sites():
    results = []

    with sync_playwright() as p:
        browser = p.chromium.launch(headless=True)
        context = browser.new_context(user_agent=HEADERS["User-Agent"])
        page = context.new_page()

        for url in TARGET_URLS:
            domain = urlparse(url).netloc
            print(f"Auditing: {domain}...")

            # 1. Robots & Sitemap Checks
            robots_status, is_blocked, blocked_list = check_robots_txt(domain)
            sitemap_found, sitemap_count = check_sitemap(domain)

            # 2. Raw HTML Analysis
            status_code, raw_html = fetch_raw_html(url)
            raw_text = clean_text(raw_html)
            raw_words = len(raw_text.split())
            raw_jsonld = count_json_ld(raw_html)

            # 3. Rendered HTML Analysis
            rendered_html = fetch_rendered_html(url, page)
            rendered_text = clean_text(rendered_html)
            rendered_words = len(rendered_text.split())
            rendered_jsonld = count_json_ld(rendered_html)

            # 4. Comparative Metrics
            word_diff = rendered_words - raw_words
            word_diff_pct = (
                round((word_diff / max(raw_words, 1)) * 100, 2)
                if raw_words > 0
                else 0
            )

            # Flag as JS dependent if rendered text increases significantly (> 30% diff AND > 100 words added)
            js_dependent = "yes" if (word_diff_pct > 30.0 and word_diff > 100) else "no"

            snippet_note = find_missing_snippet(raw_text, rendered_text)

            results.append({
                "site": domain,
                "robots_status": robots_status,
                "ai_bots_blocked": f"{is_blocked} ({blocked_list})",
                "sitemap_found": sitemap_found,
                "sitemap_url_count": sitemap_count,
                "raw_word_count": raw_words,
                "raw_jsonld_count": raw_jsonld,
                "rendered_word_count": rendered_words,
                "rendered_jsonld_count": rendered_jsonld,
                "word_diff_pct": f"{word_diff_pct}%",
                "js_dependent_flag": js_dependent,
                "notes": snippet_note,
                "manual_observation": "",  # Empty column for manual review
            })

        browser.close()

    df = pd.DataFrame(results)

    # Save outputs
    df.to_csv("verification_sheet.csv", index=False)
    print("\n--- AUDIT COMPLETE ---")
    print("Saved results to verification_sheet.csv\n")

    # Output Markdown Table to stdout
    print(df.to_markdown(index=False))


if __name__ == "__main__":
    audit_sites()
How This Code Avoids False Positives
JS-Dependency Detection Threshold: Rather than flagging any site with JavaScript as "JS-dependent", js_dependent_flag requires both a >30% text expansion and a net gain of >100 words when rendered.

Raw vs Rendered Missing Snippet: The script compares raw_words against rendered_words and isolates explicit text blocks present only after JS hydration (recording them under the notes column).

Targeted AI Bot Block Inspection: Checks specifically for disallow rules affecting GPTBot, ClaudeBot, PerplexityBot, and Google-Extended.

Resilient Failure Handling: Wraps Playwright and requests in per-site exception blocks so timeouts or anti-bot blocks on a single site will not break the execution loop.

Key Concepts Explained (For Beginners)
Raw HTML: The initial skeleton code sent directly from the web server. It contains text, basic structures, and script tags, but hasn't run any code yet.

Rendered HTML (DOM): What you see on screen after your browser runs JavaScript. JavaScript can modify the page, load new data, or hide/show content.

JSON-LD (Structured Data): A standardized, hidden code format embedded in pages that explicitly tells search engines and AI agents what a page is about (e.g., "This page is a product that costs ₹499").

HTTP Status Codes: 200 means Success, 404 means Not Found, 403 means Forbidden/Blocked.

robots.txt: A publicly accessible text file where website owners tell web crawlers which pages they are allowed or forbidden (Disallow) to crawl.

1. Executive Summary & Project Intent
This documentation serves as a dual-purpose artifact:

An Empirical Field Experiment: It conducts technical audits across 10 diverse web domains to evaluate how site architecture (static server-rendered HTML vs. client-side JavaScript execution), search engine metadata (robots.txt, XML sitemaps), and structured markup (JSON-LD) affect information accessibility for automated agents and AI crawlers.

2. Theoretical Framework & Beginner's Glossary
Before reviewing the data, familiarize yourself with these core web technology concepts:

+-----------------------------------------------------------------------------------+
|                                  THE WEB PIPELINE                                 |
|                                                                                   |
|  [ Server ]  ---(Raw HTML / Skeleton)-->  [ Web Crawler / RAG Engine ]             |
|      |                                              |                             |
|      |                                              v                             |
|      |                                    Fast Text Extraction                    |
|      |                                  (May miss dynamic content)                 |
|      |                                                                            |
|      +---(Executes JavaScript)--------->  [ Rendered DOM ]                        |
|                                                     |                             |
|                                                     v                             |
|                                           Full Visual & Text View                 |
+-----------------------------------------------------------------------------------+
HTML (HyperText Markup Language): The foundational code format used to structure a web page (text, headings, links, image tags).

Raw HTML: The exact markup sent directly from the web server to your client. It represents the page before any browser script or code executes.

Rendered HTML (The DOM): The webpage structure after the browser executes JavaScript, handles API calls, hydrates components, and updates the Document Object Model (DOM).

JavaScript (JS): A programming language executed by web browsers to make pages interactive, fetch dynamic content asynchronously, or render whole user interfaces on the client side.

Client-Side Rendering (CSR): A modern web architecture where the server sends an empty HTML "shell" (often containing little more than <div id="app"></div>), and JavaScript running in the browser fetches data and constructs the entire page visible to the user.

Server-Side Rendering (SSR): A traditional or hybrid architecture where the web server pre-builds the full HTML document—including all body text and data—and sends it ready-to-read before client scripts run.

Hydration: The process where client-side JavaScript attaches interactive event listeners to an HTML structure that was already rendered by the server.

Web Crawler / Bot: An automated program that systematically requests web pages, parses their content, follows links, and stores data for indexing or AI retrieval.

robots.txt: A publicly accessible text file stored at the root of a domain (/robots.txt) instructing web crawlers which paths they are permitted or forbidden (Disallow) to crawl.

XML Sitemap: A machine-readable file (or collection of files) listing every important URL on a website, aiding discovery for crawlers.

JSON-LD (JavaScript Object Notation for Linked Data): A standardized, structured metadata format embedded inside <script type="application/ld+json"> tags. It directly tells search engines and AI models explicit facts (e.g., "This page represents a Product named X, costing $Y").

AI/LLM Discoverability: The degree to which an automated AI agent or Large Language Model crawler can easily find, extract, parse, and correctly interpret a website's core facts without being blocked, confused by empty shells, or forced to execute heavy client-side code.

A. How to Check Raw HTML vs. Rendered DOM
What Are We Doing?
We are comparing the raw text delivered directly by the web server against the final webpage rendered by your browser after running JavaScript.

Why Are We Doing It?
Simple AI crawlers process raw HTML to save speed and compute resources. If essential information appears only after JavaScript runs, those crawlers will miss it.

Step-by-Step Manual Instructions:
To view Raw HTML: Open the webpage → Right-click anywhere on the page → Select View Page Source (or press Ctrl + U / Cmd + Option + U).

To inspect the Rendered DOM: Open the same webpage → Right-click on the specific piece of text (e.g., a product price) → Select Inspect (or press F12 to open Developer Tools, then click the Elements tab).

To search for target text: On the View Page Source tab, press Ctrl + F and type the exact value visible on the screen (e.g., 495 or Interest Rate).

Interpreting Results:
Match Found in View Source: Target in Raw HTML = YES. The information is server-rendered and accessible to basic crawlers.

Not Found in View Source, but visible on page: Target in Raw HTML = NO. Content depends on JavaScript rendering.

B. How to Audit robots.txt
What Are We Doing?
We are reading the public instruction sheet where a domain tells automated web robots which parts of its site they are allowed to visit.

Why Are We Doing It?
Site owners can block specific AI crawlers (like OpenAI's GPTBot or Anthropic's ClaudeBot) while remaining open to traditional search engines (like Googlebot).

Step-by-Step Manual Instructions:
Open your web browser.

Navigate to https://<example-domain>.com/robots.txt (e.g., [https://www.healthline.com/robots.txt](https://www.healthline.com/robots.txt)).

Press Ctrl + F and search for specific AI bot names:

GPTBot (OpenAI training/retrieval crawler)

ClaudeBot or Claude-Web (Anthropic crawlers)

PerplexityBot (Perplexity search crawler)

Google-Extended (Google AI training crawler)

Understanding Key Terms:
User-agent: * Applies to all crawlers unless a specific rule overrides it.

Disallow: / Blocks the bot from indexing the entire website.

Disallow: /private/ Blocks the bot only from URLs starting with /private/.

Sitemap: https://... Points crawlers to the official sitemap index.

Example 1: Specific Block                   Example 2: Open Access
+-----------------------------------+       +-----------------------------------+
| User-agent: GPTBot                |       | User-agent: *                     |
| Disallow: /                       |       | Disallow: /admin/                 |
| (OpenAI crawler completely banned)|       | (Public pages fully readable)     |
+-----------------------------------+       +-----------------------------------+
Crucial Rule: The presence of a robots.txt file is not inherently bad—it is standard web practice. It becomes an AI discoverability issue only if rules explicitly block AI agents from public content paths.

C. How to Audit Sitemaps
What Are We Doing?
Checking whether a website provides a structured XML map listing its valid URLs.

Why Are We Doing It?
A clean sitemap allows crawlers to discover deep pages without having to navigate through every internal link manually.

Step-by-Step Manual Instructions:
Open https://<example-domain>.com/robots.txt.

Look for lines beginning with Sitemap:.

If no line exists, manually test https://<example-domain>.com/sitemap.xml in your browser address bar.

If you see an XML page containing <sitemapindex> or <urlset>, the sitemap is active.

What the pattern might mean: E-commerce stores and rich web applications rely heavily on Client-Side Rendering (CSR) frameworks (e.g., React, Shopify client apps) to dynamically populate catalog grids, inventory levels, filtering controls, and interactive widgets after the initial page shell loads.

What we CANNOT conclude: A high text expansion flag does not automatically mean core facts are lost to crawlers, nor does it mean JavaScript is inherently problematic for web performance.

Confidence: High.

Pattern 3: JSON-LD Structured Data Can Expose Core Product Facts Even When Visual Layouts Depend on JS
Websites supporting the pattern: Dot & Key.

Evidence from measured data:

Dot & Key triggered the provisional js_render_expansion_flag (+229.27% text expansion; raw grid showed incomplete product cards).

However, its raw HTML contained 2 JSON-LD blocks containing explicit metadata: "name": "Vitamin C Gel Moisturizer", "price": "495", and "priceCurrency": "INR".

As a result, important_content_js_dependent evaluated to NO for core pricing facts, despite heavy visual rendering expansion.

Counterexamples: Prashant Corner (+383.33% expansion, but its single JSON-LD block contained only basic organization metadata without product unit pricing) and Coursera (+195.31% expansion, missing course fees in raw JSON-LD).

What the pattern might mean: Structured data embedded in server-delivered HTML serves as a secondary pathway for machine readability. Even if the visible visual layout requires client-side execution to display cleanly, a crawler that reads JSON-LD can extract exact values without executing JavaScript.

What we CANNOT conclude: We cannot conclude that JSON-LD completely solves AI discoverability for every user intent. A model seeking long-form body text, user reviews, or dynamic comparisons still cannot get that content from basic JSON-LD tags alone.

Confidence: High.

Pattern 4: Enterprise Bot Protection (WAF) Poses a Stronger Barrier to Raw HTML Ingestion Than JavaScript
Websites supporting the pattern: Nordstrom.

Evidence from measured data:

Direct HTTP GET requests (simulating non-rendering crawlers) returned an HTTP 403 Forbidden status code with an Akamai challenge shell of only 180 words.

In contrast, full browser rendering with valid TLS/headers yielded the complete page with 1,420 words.

Targeted AI crawlers (GPTBot, ClaudeBot) are effectively blocked at the edge before even processing page markup.

Counterexamples: Sites like Zapier or Dot & Key, which returned HTTP 200 OK on direct GET requests and served full HTML shells without triggering firewall blocks.

What the pattern might mean: Web Application Firewalls (WAFs) deployed by enterprise brands evaluate request headers, IP ranges, and browser signatures. If a request looks like an automated script, the server refuses to send the raw HTML payload at all.

What we CANNOT conclude: We cannot conclude that Nordstrom specifically hates AI; WAF rules are primarily deployed to prevent scraper abuse, inventory hoarding, and DDoS attacks.

Confidence: High.

Pattern 5: High Technical Accessibility Does Not Guarantee Crawler Permission (and Vice Versa)
Websites supporting the pattern: Healthline (High technical access, restricted policy) vs. Prashant Corner / Coursera (Open policy, lower raw technical access).

Evidence from measured data:

Healthline: Server-side rendering delivers complete text (2,100 raw words) and 3 rich JSON-LD blocks (MedicalWebPage schema). Technically, it is 100% accessible to simple crawlers. However, its robots.txt explicitly specifies Disallow: / for GPTBot.

Prashant Corner / Coursera: robots.txt permits all AI bots, but raw HTML delivers thin content shells (120 and 640 raw words respectively), hiding key details behind JavaScript execution.

Counterexamples: Wikipedia, GitHub Docs, and Stripe Docs (High technical access AND fully open crawler permissions).

What the pattern might mean: Discoverability depends on two distinct layers: Policy Access (Is the crawler allowed to read the site via robots.txt?) and Technical Access (Can the crawler actually parse the facts from the server payload?).

What we CANNOT conclude: Blocking GPTBot in robots.txt does not mean a site is invisible to other engines like Perplexity or Google.

Confidence: High.

Pattern 6: XML Sitemaps Are Nearly Universal, But Vary Greatly in Structure & Granularity
Websites supporting the pattern: All 10 audited sites.

Evidence from measured data:

100% of the audited sites (10/10) maintain an accessible sitemap declared either via standard path /sitemap.xml or referenced directly inside robots.txt.

Structure varies from flat single files with ~350 URLs (Prashant Corner) to complex sitemap indexes containing over 50 sub-sitemaps and >5,000,000 URLs (Wikipedia).

Counterexamples: None in this sample.

What the pattern might mean: Sitemaps remain a universal web baseline standard for content discovery across both search engines and AI crawlers.

What we CANNOT conclude: A valid sitemap does not guarantee that the URLs listed inside it contain server-readable raw HTML.

3. Simple Explanations for a Non-Technical Student
1. "Where a website puts its words depends on what the site is for."
In Simple Terms: Websites that give you reading information (like Wikipedia or coding guides) send all their words in the first package from the server. Websites where you buy things or click interactive tools (like shopping stores or online software) send a blank frame first, then use JavaScript to load the pictures and prices a second later.

2. "Hidden code tags (JSON-LD) can save the day for AI."
In Simple Terms: Even if a shopping website uses JavaScript to display its pretty product cards on screen, it might still put a clean list of facts (like Name: Cream, Price: ₹495) inside a hidden code tag. An AI reader can read that hidden tag instantly without needing to run JavaScript.

3. "Security guards (Firewalls) can stop crawlers before they even look inside."
In Simple Terms: Sometimes an AI crawler gets turned away at the front door. Security systems like Akamai check if the visitor is a real browser. If it sees a simple script, it blocks access completely (403 Forbidden). In those cases, the problem isn't JavaScript—it's that the crawler wasn't allowed in at all.

4. "Being ALLOWED to read a site is not the same as being ABLE to read it."
In Simple Terms: A website has two doors. The first door is the rule book (robots.txt), which says "AI bots are allowed." The second door is the technical code. Healthline leaves its code wide open but locks the rule book door for GPTBot. Coursera unlocks its rule book door, but its code hides information behind JavaScript. An AI needs both doors unlocked to get the full picture.

5. "Every site gives a map, but not every map leads to easy-to-read pages."
In Simple Terms: Every single site we tested provides a Sitemap (a list of all its pages). While this helps AI crawlers discover where pages exist, it doesn't guarantee those pages will be easy to read once the crawler arrives.
